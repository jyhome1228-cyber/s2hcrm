# S2H CRM UI 운영 기준 (2026-11-24)

## 방향
플로우·잔디 등 국내 업무 SaaS의 사용성을 참고하되 디자인을 복제하지 않는다. S2H 고유 로고와 브랜드 블루를 유지한다. 화이트 배경에 명확한 정보 구조, 가독성 높은 목록, 줄 단위 작업을 기본으로 한다.

## 컬러
- Primary: `#0089B3` / hover `#006F94`
- Background: `#FFFFFF`
- Text: `#22292E`
- Secondary text: `#556269`
- Muted text: `#718087`
- Divider: `#DFE5E8`
- Hover: `#F3F8FA`
- 상태 색상은 불필요하게 여러 색을 쓰지 않는다. 진행 중은 S2H 블루, 예정은 블루 아웃라인, 완료는 회색 중심.

## 레이아웃 및 타이포그래피
- 사이드바 고정 폭 232px(중간 해상도 208px), 모바일은 가로 스크롤 내비게이션.
- 상단 헤더 64px, 현재 페이지 표시, 실행 가능한 셀러 검색, 사용자·로그아웃.
- 콘텐츠 최대 폭 1560px, 데스크톱 기본 좌우 패딩 40px.
- 서체 Pretendard 우선. 페이지 제목 26px, 패널 제목 17px, 본문 13–14px, 보조 12px.
- 둥근 카드를 반복하지 않는다. 2–4px 라운딩, 얇은 구분선, 최소한의 그림자.
- 기본 버튼 높이 40px, 미니 버튼 약 31px, 표 셀 높이는 행 패딩으로 정렬.
- 포커스, hover, disabled, 로딩, 빈 상태를 생략하지 않는다.

## 공통 컴포넌트
- `ui-system.css`: 인증 후 앱 셸, 공통 버튼·테이블·인풋·기본 모달.
- `dashboard-v4.css`: 대시보드와 기간형 공구 캘린더. 날짜·막대 그리드 높이 유지.
- `buy-editor.css`: 공구 등록·수정 전용. 기본 정보, 운영 정보, 추가 정보.
- `styles.css`: 기존 앱 기능·기반 스타일. 새 CSS는 이 파일을 대체하지 않는다.

## 동작 원칙
- 기존 Firebase 스키마와 셀러·상품·공구·활동 내역을 변경하지 않는다.
- 사이드바 페이지 이동, 셀러 검색, 공구 등록·수정, 선택한 날짜 등록, 캘린더 기간 표시·더보기는 동작해야 한다.
- 현 점검 모드(`MAINTENANCE_MODE`)는 최종 검수 전까지 유지한다.
- 기능 검수 전에는 "운영 전환 완료"를 표시하지 않는다.

## 단계별 작업
- **STEP 1** 공통 UI 시스템: 셸/내비게이션/타이포그래피/버튼/테이블/모달 통일
- **STEP 2** 핵심 업무 화면: 대시보드/캘린더/셀러/상품/활동 정보 위계 및 인터랙션 고도화
- **STEP 3** 오픈 준비 체크리스트, 담당자·알림·이력, Firebase 권한과 전체 QA 후 점검 종료
